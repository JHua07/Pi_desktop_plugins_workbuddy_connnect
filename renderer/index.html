首次配置一次 · Windows 登录后自动运行

WorkBuddy Connect

将自己的 WorkBuddy / WorkBuddy AI 账号接入 PI 的原生模型设置。

接入管理界面

配置 Base URL、显示/复制/重新生成 Key、查询认证状态与模型列表、管理 Windows 登录自启动。

桌面「PI WorkBuddy Connect.url」只打开管理页，不运行脚本。首次进入请输入本地 Key；需自动启动及一次性授权时，运行下方 ui 命令。默认端口 18765。

node .\bridge\cli.cjs ui

先了解接入方式

官方 PI 插件 SDK 没有模型提供商注册、进程执行或网络服务器 API。本插件仅提供配置指南，不能自动注册模型，也不能启动桥接服务。

面板不访问外部网络、不读取凭据、不接收 API Key。独立伴随服务可通过下方命令启用 Windows 登录自启动，之后无需保持终端开启。

1 · 准备账号与运行环境

安装并登录你自己的 WorkBuddy（国内）或 WorkBuddy AI（国际）应用，安装 Node.js 22.19+。两个渠道的凭据与模型目录相互隔离。

保留解压后的完整源码目录，在该目录打开 PowerShell。下面的命令均相对于源码目录；安装 .piplug 并不会启动服务。

node .\bridge\cli.cjs automation install

首次执行一次：创建当前用户的计划任务并立即后台启动。以后登录 Windows 自动运行；每分钟检查认证，按五分钟缓存刷新模型目录。先关闭旧的前台桥接，保留源码目录不要移动。

node .\bridge\cli.cjs service

service 查看自动刷新和模型数量，不发送聊天请求。停止用 automation stop，重新启动用 automation start；删除自启动用 automation uninstall，密钥和凭据副本保留。

node .\bridge\cli.cjs key

key 输出的是本地桥接 API Key，不是 WorkBuddy token。只将该值填入 PI 原生模型设置，不要粘贴到本面板或分享给他人。

2 · 在 PI 设置 → 模型中添加提供商

提供商
OpenAI 兼容 · Chat Completions
账号名称
WorkBuddy 或 WorkBuddy AI
API 类型
openai-completions（如需选择；不是 Responses）
API Key
上述 key 命令输出的本地密钥

WorkBuddy · 国内 Base URL

http://127.0.0.1:18765/workbuddy/v1

WorkBuddy AI · 国际 Base URL

http://127.0.0.1:18765/workbuddy-ai/v1

按实际登录渠道选择地址，不要混用。通过 PI_WORKBUDDY_PORT 更改端口时，请同步替换 URL 中的 18765；本面板不会修改服务配置。

3 · 获取并选择准确的模型 ID

node .\bridge\cli.cjs models workbuddy
node .\bridge\cli.cjs models workbuddy-ai

运行中的服务自动获取模型目录，无需反复执行查询命令。PI 若支持拉取模型，可使用标准 /models；否则首次填写准确模型 ID。自动刷新不会自动改写 PI 已保存的模型列表，也不会发送付费聊天请求。

保存后再按需进行真实对话。真实聊天可能消耗账号额度，当前账号的真实聊天尚未验证，离线测试不代表线上接入成功。

边界与安全提醒

伴随服务借鉴 MIT 上游的 token 刷新和加密凭据处理，仅以只读方式读取原始凭据；本地密钥、缓存和刷新后的凭据副本存储在 PI_WORKBUDDY_HOME（默认 ~/.pi-workbuddy-connect）。

必要时，解密助手会调用已安装的 WorkBuddy Electron 程序。Windows ACL 不是完美沙箱，同一 Windows 用户下的进程仍可能访问这些文件。详细环境变量与上游来源见 README。

WorkBuddy 私有接口可能变化。仅供个人学习、本人账号使用，请遵守服务条款；这不是官方集成，也不是零配置接入。
